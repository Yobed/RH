# Plan: 02-07 Import Excel Heures Supplémentaires par Période

<objective>
Les RH peuvent importer en masse les heures supplémentaires de tous les employés pour une période donnée via un fichier Excel, afin que ces données soient automatiquement prises en compte dans le calcul du salaire net de la période concernée. Le flux suit le même pattern que l'Import Paie Sage (Phase 8) : téléchargement d'un template → saisie offline → upload → validation → application au moteur de paie.
</objective>

```sql
-- Table de traçabilité des imports heures supplémentaires
CREATE TABLE IF NOT EXISTS overtime_import_logs (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id   UUID NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  employee_id  UUID REFERENCES employees(id) ON DELETE SET NULL,
  matricule    TEXT NOT NULL,              -- Valeur brute du fichier importé
  periode      TEXT NOT NULL,             -- Format YYYY-MM
  h15          NUMERIC(5,2) NOT NULL DEFAULT 0,
  h50          NUMERIC(5,2) NOT NULL DEFAULT 0,
  h75          NUMERIC(5,2) NOT NULL DEFAULT 0,
  h100         NUMERIC(5,2) NOT NULL DEFAULT 0,  -- Heures à +100% (exceptionnel)
  montant_calcule NUMERIC(12,2),          -- Calculé à l'import (FCFA)
  statut       TEXT NOT NULL DEFAULT 'importé'
               CHECK (statut IN ('importé','appliqué','annulé','erreur')),
  commentaire  TEXT,
  import_batch_id UUID NOT NULL,          -- Regroupe toutes les lignes d'un même import
  imported_by  UUID NOT NULL REFERENCES auth.users(id),
  created_at   TIMESTAMPTZ DEFAULT now()
);

-- RLS
ALTER TABLE overtime_import_logs ENABLE ROW LEVEL SECURITY;

CREATE POLICY "company_isolation" ON overtime_import_logs
  FOR ALL USING (company_id = get_user_company_id());

-- Index pour recherche par période et batch
CREATE INDEX idx_oil_company_periode ON overtime_import_logs(company_id, periode);
CREATE INDEX idx_oil_batch ON overtime_import_logs(import_batch_id);
```

Remplacer TIMESTAMP par l'horodatage réel au format YYYYMMDDHHMMSS.

```typescript
// Colonnes obligatoires du template
export const REQUIRED_COLUMNS_HS = ['matricule', 'periode', 'h15', 'h50', 'h75', 'h100'] as const;

// Type pour une ligne brute du fichier
export interface LigneImportHS {
  matricule: string;
  periode: string;     // YYYY-MM
  h15: number;
  h50: number;
  h75: number;
  h100: number;        // Heures à +100% — exceptionnel (nuit dimanche/férié cumulé)
  commentaire?: string;
}

// Type pour une ligne validée et enrichie
export interface LigneValideeHS extends LigneImportHS {
  employee_id: string;
  nom_complet: string;
  taux_horaire: number;
  montant_calcule: number;
}

// Type pour le résultat de validation
export interface ResultatValidationHS {
  valides: LigneValideeHS[];
  erreurs: Array<{ ligne: number; matricule: string; raison: string }>;
  periode: string;  // Période extraite (unique attendue)
  total_montant: number;
}

/**
 * Parse un fichier Excel (Buffer) et retourne les lignes brutes.
 * Nettoie espaces insécables (\u00A0), convertit virgules décimales.
 */
export function parseExcelHS(buffer: Buffer): LigneImportHS[]

/**
 * Valide les lignes parsées contre la liste des employés actifs.
 * - Vérifie que le matricule correspond à un employé actif de l'entreprise
 * - Vérifie que la période est au format YYYY-MM
 * - Vérifie que h15, h50, h75, h100 >= 0
 * - Calcule montant_calcule via calculerHeuresSup() de lib/paie-ci.ts (étendu avec h100)
 * - Calcule le taux horaire = salaire_brut / 173.33 si non fourni
 */
export function validerLignesHS(
  lignes: LigneImportHS[],
  employees: Array<{ id: string; matricule: string; full_name: string; salaire_brut: number }>
): ResultatValidationHS
```

Règles de validation métier :
- Si un matricule ne correspond à aucun employé actif → erreur ligne
- Si h15 + h50 + h75 + h100 === 0 → avertissement (non bloquant, ligne acceptée)
- Si la période n'est pas au format `^\\d{4}-(0[1-9]|1[0-2])$` → erreur ligne
- Si plusieurs périodes différentes dans le même fichier → erreur globale
- Maximum 500 lignes par import (protection mémoire)
</action>

```typescript
// POST /api/heures-sup/import
// Content-Type: multipart/form-data
// Body: file (Excel), periode (YYYY-MM optionnel — override colonne)

export async function POST(request: Request) {
  // 1. Auth + company_id (pattern standard)
  // 2. Parse multipart — extraire le Buffer du fichier .xlsx
  // 3. parseExcelHS(buffer) → lignes brutes
  // 4. Charger les employés actifs de la company (id, matricule, full_name, salaire_brut)
  // 5. validerLignesHS(lignes, employees) → { valides, erreurs, periode, total_montant }
  // 6. Si erreurs.length > 0 et valides.length === 0 → retourner 422 avec liste d'erreurs (aucune écriture)
  // 7. Si valides.length > 0 :
  //    a. Générer import_batch_id = crypto.randomUUID()
  //    b. INSERT INTO overtime_import_logs (toutes les lignes valides en une seule requête)
  //    c. INSERT INTO overtime_records (une ligne par employé valide, statut = 'importé')
  //       — Réutiliser la structure existante overtime_records avec source = 'import_excel'
  // 8. Retourner JSON : { importé: N, erreurs: [...], batch_id, periode, total_montant }
}
```

**Règle critique :** Si le fichier contient des erreurs ET des lignes valides, retourner 422 avec toutes les erreurs — **zéro écriture en base**. L'import est atomique.

- `company_id` : depuis le profil utilisateur
- `employee_id` : UUID résolu par le matricule
- `date` : premier jour de la période (ex: 2026-05-01 pour periode=2026-05)
- `h15`, `h50`, `h75`, `h100` : depuis LigneValideeHS
- `montant` : montant_calcule de LigneValideeHS
- `source` : 'import_excel' (nouveau champ — ajouter IF NOT EXISTS dans migration si absent)
- `notes` : commentaire de la ligne
