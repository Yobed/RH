# Plan: 02-05 Multi-convention collective

<objective>
Permettre de configurer les règles de calcul spécifiques (primes d'ancienneté, sursalaires, indemnités) basées sur la convention collective choisie par l'entreprise (ex: CCI, BTP, Commerce).
</objective>

<tasks>

<task>
<description>Mettre en place la table `fiscal_params` par entreprise.</description>
<read_first>
- supabase/migrations/...
</read_first>
<action>
1. Créer une nouvelle migration `supabase/migrations/$(date +%Y%m%d%H%M%S)_fiscal_params.sql`.
2. Définir une table `fiscal_params` : `id`, `company_id (FK)`, `convention` (texte: BTP, CCI, Commerce, etc.), `valeur_point` (numeric), `created_at`, `updated_at`.
3. Assurez-vous des RLS policies : SELECT/INSERT/UPDATE où `company_id = get_user_company_id()`.
</action>
<acceptance_criteria>
- La base de données héberge le moyen d'attacher une convention de calcul par compagnie.
- Les RLS de cette table s'assurent que la data est ségréguée par Tenant.
</acceptance_criteria>
</task>

<task>
<description>Gérer l'interface de choix de Convention / Paramètres globaux.</description>
<read_first>
- components/settings/ParametresForm.tsx
- app/api/settings/route.ts
</read_first>
<action>
1. À l'écran Paramètres de la Compagnie, ajouter la lecture de `fiscal_params` pour remplir un `<Select />` avec des valeurs comme "Interprofessionnelle (CCI)", "BTP", etc.
2. Lorsqu'enregistré via l'API, sauver (Upsert) le choix ou mettre à jour la ligne où l'entreprise est la bonne.
</action>
<acceptance_criteria>
- Un utilisateur peut configurer les attributs propres à la convention collective et les sauver sans errer.
- L'appel GET `/api/settings` ou `GET /api/paie` extrait ladite convention pour adapter le calcul salarial via `lib/paie-ci.ts` à l'avenir.
</acceptance_criteria>
</task>

</tasks>

<verification>
1. Les API qui lisent la table `fiscal_params` ne lisent pas celles des autres entreprises.
</verification>

<must_haves>

- L'entreprise peut choisir sa convention selon le contexte fiscal CI.
</must_haves>
