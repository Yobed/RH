# Phase 06: Module Disciplinaire - Plan d'implémentation

## Objectif
Mettre en place le module de gestion des procédures disciplinaires conformément au droit du travail ivoirien. Ce module permettra aux responsables RH de gérer les conflits, d'initier des demandes d'explication, d'appliquer des sanctions et de générer automatiquement les documents légaux nécessaires.

## Fonctionnalités Clés
- **Tableau de bord disciplinaire** : Vue d'ensemble des procédures en cours et passées concernant les employés.
- **Workflow de procédure** : Suivi des demandes d'explication (Demande → Réponse de l'employé → Décision / Sanction).
- **Modèles de courriers générés** : Convocation à un entretien préalable, notification de licenciement (faute lourde, économique), avertissement, mise à pied, et mise en demeure (abandon de poste).
- **Conformité & Délais** : Suivi des délais légaux pour les réponses et l'application des sanctions.

## Étapes d'implémentation

### 1. Base de données & Typage
- Création d'une table `disciplinary_procedures` :
  - Colonnes : `id`, `company_id`, `employee_id`, `type` (Demande d'explication, Avertissement, Mise à pied, Licenciement), `motif` (TEXT), `statut` (BROUILLON, EN_COURS, ATTENTE_REPONSE, SANCTION_APPLIQUEE, CLOTURE, ANNULE), `date_incident`, `date_notification`, `reponse_employe` (TEXT), `sanction_appliquee` (TEXT), `documents_urls` (JSONB).
  - Politique RLS : Filtrage strict par `company_id`.
- Génération de la migration SQL et exécution locale.
- Mise à jour du fichier `types/supabase.ts`.

### 2. Développement API Backend
- Création des routes d'API :
  - `POST /api/disciplinaire` : Lancer une nouvelle procédure.
  - `GET /api/disciplinaire` : Lister les procédures de l'entreprise.
  - `PATCH /api/disciplinaire/[id]` : Mettre à jour le statut, enregistrer une réponse d'employé, ou lier un document généré.
- Implémentation du générateur de modèles via Gemini Flash (ex: `/api/disciplinaire/[id]/generer-document`) en fournissant des prompts adaptés au droit ivoirien ciblé par la procédure.

### 3. Interface Utilisateur (Frontend)
- **`app/(dashboard)/disciplinaire/page.tsx`** : Page de liste des procédures avec fonctions de filtre (Statut, Date, Type).
- **`components/rh/DisciplinaryDialog.tsx`** : Formulaire de création d'une nouvelle procédure avec sélection de l'employé, type d'infraction, date et description factuelle.
- **`app/(dashboard)/disciplinaire/[id]/page.tsx`** : Vue détaillée d'une procédure permettant d'opérer le cycle de vie complet (enregistrer la réponse, choisir la sanction, etc.).
- **Génération Documentaire UI** : Boutons d'action pour pré-visualiser et imprimer/télécharger (PDF/Word) les courriels disciplinaires types.

## Critères de Validation (UAT)
- [ ] Une procédure peut être créée, modifiée et clôturée avec des statuts clairs.
- [ ] Les données de chaque entreprise sont compartimentées (RLS validé).
- [ ] L'application permet la génération automatique par IA d'un courrier (ex. Demande d'explication) sur la base du motif fourni.
- [ ] La compilation TS est de 100% clean.
